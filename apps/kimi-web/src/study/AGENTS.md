# Kimi Study implementation rules

These instructions apply to `apps/kimi-web/src/study/**`.

## Remote authority and preflight

The implementation agent may use the operator-provided remote target through:

```bash
ssh -o BatchMode=yes "${STUDY_SSH_TARGET:?Set STUDY_SSH_TARGET}" 'command'
```

Set `STUDY_REPO` to the authoritative worktree path before running repository commands.

Before editing, inspect the real state instead of assuming it:

```bash
git -C "${STUDY_REPO:?Set STUDY_REPO}" worktree list --porcelain
git -C "${STUDY_REPO}" status --short --branch
# Inspect every sibling worktree reported above before touching it.
```

- `feat/kimi-study-frontend` contains user/agent-owned uncommitted work. Do not edit, reset, clean, stash, or overwrite it.
- `feat/kimi-study-coursebox-replica` may also contain uncommitted comparison work. Do not touch it without a new explicit instruction.
- The authoritative foundation worktree is on `feat/kimi-study-foundation`; resolve its path from `git worktree list`.
- Recheck server readiness and installed Skill contracts; session Skill catalogs are snapshots and old sessions do not discover newly installed Skills.
- Ask before every commit. Keep one logical change per commit; never combine API, domain/runtime, Skill, and UI work in one commit.

## Product promise

Kimi Study starts from material, never from a one-line topic prompt.

- Uploaded material gets one decision: Quick (recommended) or Deep.
- Catalog material is already source-certified by Deep/RIA and does not ask for a mode.
- Quick surveys the entire material at honest survey depth and asks 0–1 Mission questions.
- Deep reads the whole supported source, runs RIA verification, and asks 2–4 adaptive Mission questions concurrently.
- Preprocessed catalog packages reuse source-bound understanding only. Every learner still gets a new Mission-bound blueprint.
- Internal analysis is auto-approved by default after quality gates. Never ask learners to approve decomposition, RIA units, overview, blueprint rows, or lesson counts.

## Stable UI seam

Import the product surface from `./foundation`:

```ts
import {
  useStudyProduct,
  parseCatalogPackageManifest,
  type StudyProductView,
} from './foundation';
```

Do not call `KimiWebApi`, raw REST, WebSocket, session profile, model, permission, or Skill activation from Vue components. Add a product action to the Controller/runtime seam first.

The composable exposes only learner/product actions:

- readiness;
- upload material;
- select Quick or Deep once;
- select a certified catalog package;
- answer/skip/dismiss one Mission question card;
- refresh/resume;
- generate the current plan;
- upgrade Quick to Deep.

Do not expose Kimi Code title, model selector, permission mode, plan mode, swarm mode, raw tool output, raw Skill names, checker terms, RIA/V1/A1 labels, or workspace paths.

## State and trust

- `source/STUDY-SNAPSHOT.json` is course truth for product state.
- Chat is narration and tutor interaction, not the state database.
- The browser registry stores resumable pointers and operation ids only.
- Never infer readiness from message count, token output, file count, or optimistic UI timing.
- Missing/malformed/truncated/stale artifacts stay missing, unavailable, unsafe, or blocked. Never invent readiness.
- Generate only when plan source/Mission revisions match the current snapshot.
- Quick evidence is `survey`; it can never become `certified` without switching to Deep.
- Catalog material must come from `parseCatalogPackageManifest`. Do not cast or manually construct `CertifiedCatalogMaterial`.

## UX contract

Preserve the Coursebox-quality interaction rhythm while using Kimi Study's material-first advantage:

1. Home begins with upload and a catalog of prepared materials; no prompt-suggestion list such as “teach my dad to identify scams.”
2. After upload, show one clear Quick/Deep choice. Recommend Quick for exploration and Deep for known textbooks, coursework, or exercises.
3. Show source work and Mission clarification as parallel progress, not a developer transcript.
4. Render only validated native question cards: one question, 2–4 options, optional “other,” skip, and close.
5. Move to the outline automatically after evidence + Mission join. Internal approvals are invisible.
6. Generate from the visible current outline revision and publish lessons incrementally.
7. Learner view uses a chapter tree, progress, lesson content, previous/next, and a page-context tutor drawer.

Every public question generated by the agent passes the same internal-term guard as UI copy. If it fails, show a product error and do not leak the raw question.

## UI implementation

- The UI agent owns `StudyApp.vue`, route/view composition, transitions, and Coursebox visual parity.
- Use kimi-web design tokens and `components/ui` primitives only. Do not invent a palette or introduce beige/orange.
- `VITE_KIMI_PRODUCT=study` mounting is wired in `main.ts` (done in the 0.5→1 UI integration); the default build still mounts the Kimi Code chat client.
- The pre-product in-memory demo and the default-chat overlay were removed. Product work happens only in `StudyApp.vue` and `components/product/`; do not reintroduce `?study-demo=1` or parallel mock state.
- Screens derive from `product/studyScreenModel.ts` (pure, tested). Product components never call `useStudyProduct` again: the shell provides the single facade through `STUDY_PRODUCT_INJECTION_KEY`.
- Outline/lesson/tutor data crosses the same trust boundary as snapshots: artifacts are read through controller actions and parsed conservatively (`parseQuickPlanOutline`, `parseLessonIndex`, `extractHtmlTitle`, `buildTutorThread`); a parse failure degrades to counts/counts-only rendering, never to invented content.
- Keep the learner flow usable when the backend is working but provider auth is not ready: show a product login/readiness state, never developer controls.
- Coursebox DOM/animation research may inform presentation, but do not copy its topic-prompt start over the material-first contract.

```bash
npm run typecheck
npm test
npm run check:style -- --strict
```

Run focused tests while iterating:

```bash
./node_modules/.bin/vitest run \
  test/study-course-foundation.test.ts \
  test/study-runtime-foundation.test.ts \
  test/daemon-client.test.ts
```

Do not claim end-to-end course generation while `/api/v1/auth` reports `ready: false`.
